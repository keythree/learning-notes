# 其它

仓库里还会遇到「仓库中的仓库」，以及提交前后自动跑的脚本。这两类不在日常提交流程里，但协作项目里常见。

## 子模块

把另一个 Git 仓库挂进当前仓库的某个路径：

```bash
git submodule add <仓库URL> 路径
```

克隆了含有子模块的项目后，子模块目录默认是空的，需要补全：

```bash
git submodule update --init --recursive
```

`--init` 按父仓库记录的提交检出子模块。`--recursive` 连子模块内部嵌套的子模块一起初始化。

父仓库提交里记录的是子模块的某一个提交哈希。子模块里有新提交时，要在父仓库里再提交一次，别人才会跟着前进。

## 钩子 hooks

Git 在特定动作前后会运行 `.git/hooks/` 里的脚本，例如：

| 钩子 | 时机 |
| --- | --- |
| `pre-commit` | `git commit` 生成提交之前 |
| `pre-push` | `git push` 发送之前 |

脚本以非 0 退出时，这次提交或推送会被取消。`.git/hooks/` 里的文件不随 `git push` 分享给别人，每人克隆后都是自己的一份。

团队要用同一套检查时，常用 [husky](https://typicode.github.io/husky/) 把钩子配置放进仓库，安装依赖时再装到 `.git/hooks/`。这样 `pre-commit` 可以跑格式化或测试，`pre-push` 可以拦住明显不该推上去的提交。

钩子适合做提醒和本地检查，不能代替远程仓库上的权限和 CI。
